# Cloudirve 网盘 MVP 设计方案

## 1. 文档定位

本文档是 Cloudirve 个人网盘 MVP 的产品与交互设计基线，服务于产品、设计、前端、后端和测试实现。除非后续需求明确变更，首版功能、页面结构、交互规则和验收标准以本文档为准。

设计系统源文件：`design-system/cloudirve-drive-mvp/MASTER.md`

## 2. 产品定义

### 2.1 产品定位

Cloudirve 是一个面向个人用户的私有文件管理器。MVP 的目标不是复刻大型云盘，而是先稳定验证一条高频主链路：

> 登录 → 浏览目录 → 上传文件 → 管理文件 → 下载文件

### 2.2 目标用户

- 需要在家庭 NAS 或个人服务器上管理文件的个人用户。
- 需要跨设备访问文档、图片、视频等常用文件的用户。
- 关注数据可控、界面简单和部署成本的技术用户。

### 2.3 MVP 目标

- 用户能够安全登录并访问自己的文件空间。
- 用户能够创建目录、上传、浏览、重命名、删除和下载文件。
- 页面刷新或服务重启后，文件元数据与文件内容仍然可用。
- 失败、越权、超限、重复文件等异常情况有可理解的反馈。
- 核心流程具备接口测试和前端交互测试，能够持续回归。

### 2.4 非目标

首版暂不实现：

- OnlyOffice 在线编辑。
- 多人协同和实时评论。
- 桌面同步客户端和移动端原生 App。
- WebDAV、多云挂载、CDN 和端到端加密。
- 复杂的团队组织、角色矩阵和多租户能力。
- 文件版本管理、去重和高级媒体处理。

## 3. 功能范围与优先级

### 3.1 P0：MVP 必须完成

| 模块 | 功能 | 验收重点 |
|---|---|---|
| 账户 | 登录、退出、会话保持 | 未登录不能访问文件接口 |
| 权限 | 用户数据隔离 | 用户只能操作自己的文件 |
| 目录 | 创建、进入、返回、重命名 | 支持多级目录和面包屑 |
| 文件 | 上传、列表、重命名、删除、下载 | 刷新后数据仍保留 |
| 上传 | 多文件、进度、大小校验、失败提示 | 重复文件有明确策略 |
| 回收站 | 删除确认、查看、恢复、永久删除 | 默认不直接物理删除 |
| 基础反馈 | 加载、空状态、错误、成功提示 | 反馈靠近触发位置 |

### 3.2 P1：MVP 后第一迭代

- 文件名和类型搜索。
- 分享链接、有效期和分享密码。
- 图片、PDF、文本文件基础预览。
- 存储空间配额和使用量展示。
- 批量选择、批量删除、批量下载。
- 分片上传、断点续传和失败重试优化。
- 操作日志和回收站自动清理。

## 4. 信息架构

```text
Cloudirve
├── 登录
└── 工作区
    ├── 我的文件
    │   ├── 根目录
    │   ├── 子目录
    │   └── 文件详情 / 操作菜单
    ├── 回收站
    └── 设置
        ├── 账户信息
        ├── 存储用量
        ├── 修改密码
        └── 退出登录
```

### 4.1 路由建议

| 路由 | 页面 | 登录要求 |
|---|---|---|
| `/login` | 登录页 | 否 |
| `/drive` | 我的文件，默认入口 | 是 |
| `/drive/:folderId` | 指定目录 | 是 |
| `/trash` | 回收站 | 是 |
| `/settings` | 设置 | 是 |

## 5. 核心用户流程

### 5.1 登录流程

1. 用户打开应用，未认证时进入 `/login`。
2. 用户填写用户名和密码，点击登录。
3. 表单提交期间按钮进入加载状态，禁止重复提交。
4. 登录成功后跳转 `/drive`。
5. 登录失败时在表单附近展示通用错误，不泄露账号是否存在。
6. 会话失效时，当前页面提示并返回登录页。

### 5.2 上传流程

1. 用户点击“上传文件”或将文件拖入上传区域。
2. 客户端先检查数量、文件大小和基础文件名规则。
3. 每个文件显示独立的等待、上传中、成功、失败状态。
4. 服务端再次校验用户权限、大小和存储配额。
5. 成功后刷新当前目录列表，并保留用户所在目录。
6. 失败项提供重试，不影响已成功文件。

### 5.3 文件操作流程

- 点击文件夹进入目录。
- 点击面包屑返回上级目录。
- 点击文件行右侧操作菜单，选择重命名、下载或删除。
- 删除操作必须二次确认，并说明文件将进入回收站。
- 下载操作显示短暂反馈；服务端校验后返回文件流。

### 5.4 恢复流程

1. 用户进入回收站。
2. 选择文件或文件夹并点击“恢复”。
3. 如果原目录仍存在，恢复到原目录；否则恢复到根目录并提示原因。
4. 永久删除必须二次确认，并明确说明不可恢复。

## 6. 页面设计

### 6.1 登录页

目标：用最少步骤完成认证，避免营销内容干扰。

- 居中登录表单，桌面端宽度约 `360px`，移动端左右留白 `24px`。
- 字段：用户名、密码。
- 主操作：登录。
- 辅助状态：提交中、登录失败、会话过期。
- 密码输入提供显示 / 隐藏按钮，按钮必须有无障碍标签。
- 不在错误信息中区分“用户名不存在”和“密码错误”。

### 6.2 文件管理页

桌面布局：

```text
┌──────────────┬──────────────────────────────────────────┐
│ 品牌 / 导航  │ 顶栏：面包屑、搜索占位、用户菜单          │
│              ├──────────────────────────────────────────┤
│ 我的文件     │ 工具栏：上传文件、新建文件夹、视图切换    │
│ 回收站       ├──────────────────────────────────────────┤
│ 设置         │ 文件列表：名称、类型、大小、修改时间、操作 │
│              │                                          │
│ 存储用量     │                                          │
└──────────────┴──────────────────────────────────────────┘
```

- 左侧导航宽度建议 `232px`，主内容使用剩余空间。
- 顶部工具栏固定在内容区域顶部，不遮挡列表。
- 列表优先使用表格密度，适合重复管理；移动端切换为文件卡片或两列网格。
- 文件夹使用蓝色图标，普通文件使用琥珀色或中性色图标，不依赖颜色单独传达类型。
- 行悬停显示操作，但所有操作必须在键盘和触摸设备可用。
- 空目录显示“上传文件”和“新建文件夹”两个直接操作。

### 6.3 回收站

- 页面标题明确为“回收站”。
- 展示原位置、删除时间和剩余保留时间（如果启用自动清理）。
- 支持恢复和永久删除。
- 永久删除按钮使用危险色，并始终二次确认。

### 6.4 设置页

- 账户信息：用户名、登录状态。
- 存储用量：已用空间、总空间、文件数量。
- 修改密码：当前密码、新密码、确认新密码。
- 退出登录：放在账户区域末尾，避免与高频文件操作混淆。

## 7. 组件规范

### 7.1 基础组件

- `AppShell`：认证后的整体布局、侧栏和主内容区域。
- `Sidebar`：主导航、存储用量、折叠状态。
- `TopBar`：面包屑、页面标题、用户菜单。
- `Toolbar`：上传、新建文件夹、批量操作、视图切换。
- `Breadcrumbs`：目录层级导航。
- `FileList`：文件和文件夹列表。
- `FileRow`：名称、类型、大小、时间、操作菜单。
- `UploadPanel`：拖拽区、进度、成功与失败项。
- `ConfirmDialog`：删除、永久删除等高风险确认。
- `Toast`：短反馈；错误信息不能只使用 Toast。
- `EmptyState`、`LoadingState`、`ErrorState`：统一页面状态。

### 7.2 关键状态

每个异步组件至少定义：

- 初始状态。
- 加载状态。
- 成功状态。
- 空状态。
- 可恢复失败状态。
- 权限失败状态。
- 网络断开状态。

### 7.3 操作菜单

- 文件：下载、重命名、删除。
- 文件夹：打开、重命名、删除。
- 回收站文件：恢复、永久删除。
- 菜单项使用 Lucide 或同类一致 SVG 图标，禁止用 Emoji 代替图标。
- 图标按钮必须提供 `aria-label` 和悬停提示。

## 8. 视觉设计系统

### 8.1 设计方向

- 风格：轻量、克制、面向工作的现代文件管理器。
- 视觉原则：信息优先、边界清晰、交互反馈及时、减少装饰。
- 不使用大面积营销 Hero、复杂渐变、3D、霓虹光效或装饰性背景。
- 卡片只用于重复项、弹窗和确实需要框定的工具，不在卡片内继续嵌套卡片。

### 8.2 颜色令牌

```css
:root {
  --color-primary: #2563eb;
  --color-primary-hover: #1d4ed8;
  --color-accent: #d97706;
  --color-background: #f8fafc;
  --color-surface: #ffffff;
  --color-muted: #f1f5f9;
  --color-foreground: #0f172a;
  --color-secondary-foreground: #475569;
  --color-border: #e2e8f0;
  --color-danger: #dc2626;
  --color-success: #15803d;
  --color-focus: #2563eb;
  --color-folder: #2563eb;
  --color-file: #d97706;
}
```

颜色只表达语义，不作为唯一信息来源。成功、错误和警告状态应同时配合文字或图标。

### 8.3 字体与排版

- 首选字体：`Plus Jakarta Sans`。
- 中文回退：`"PingFang SC", "Microsoft YaHei", sans-serif`。
- 正文基准：`16px`，行高 `1.5`。
- 页面标题：`24px`，字重 `600`。
- 区块标题：`18px`，字重 `600`。
- 列表正文：`14px` 或 `15px`。
- 辅助信息不得低于 `12px`，并确保对比度达到 `4.5:1`。

### 8.4 间距与尺寸

- 基础间距单位：`4px`。
- 常用间距：`8 / 12 / 16 / 24 / 32px`。
- 触摸和键盘操作目标最小尺寸：`44 × 44px`。
- 桌面端侧栏：`232px`，可在后续增加折叠。
- 页面内容最大宽度不做强限制，文件列表优先利用可用空间。
- 小屏断点至少验证 `375px`、`768px`、`1024px` 和 `1440px`。

### 8.5 交互与动效

- 普通颜色和边框变化：`150ms`。
- 面板和弹窗进入：`200–300ms`，使用轻量淡入或位移。
- 不使用会导致布局跳动的 hover 缩放。
- 尊重 `prefers-reduced-motion: reduce`，减少非必要动画。
- 上传进度、删除结果和错误必须有可感知反馈。

## 9. 数据与接口设计

### 9.1 数据实体

```text
users
- id
- username
- password_hash
- created_at
- updated_at

files
- id
- user_id
- parent_id
- name
- type
- size
- storage_path
- mime_type
- is_directory
- deleted_at
- created_at
- updated_at
```

约束：

- `user_id` 是所有文件查询的必选过滤条件。
- `parent_id` 指向父目录，根目录使用 `NULL`。
- 数据库元数据和物理存储路径分离。
- 物理文件名使用内部 ID，不直接使用用户原始文件名。
- 文件名在同一用户、同一父目录、未删除范围内必须有明确的重名策略。

### 9.2 MVP 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `POST` | `/api/auth/login` | 登录 |
| `POST` | `/api/auth/logout` | 退出 |
| `GET` | `/api/auth/me` | 获取当前用户 |
| `GET` | `/api/files?parentId=` | 获取目录内容 |
| `POST` | `/api/files/folders` | 创建文件夹 |
| `POST` | `/api/files/upload` | 上传文件 |
| `PATCH` | `/api/files/:id` | 重命名或更新元数据 |
| `GET` | `/api/files/:id/download` | 下载文件 |
| `DELETE` | `/api/files/:id` | 移入回收站 |
| `GET` | `/api/trash` | 获取回收站 |
| `POST` | `/api/trash/:id/restore` | 恢复文件 |
| `DELETE` | `/api/trash/:id/permanent` | 永久删除 |

接口错误统一返回：

```json
{
  "error": {
    "code": "FILE_NOT_FOUND",
    "message": "文件不存在或已被删除"
  }
}
```

前端根据 `code` 处理逻辑，`message` 作为用户可读文案。服务端日志可以记录更多细节，但不把内部路径和堆栈返回给用户。

### 9.3 存储布局

```text
data/
├── app.db
└── files/
    └── <user-id>/
        └── <file-id>
```

首版建议使用本地磁盘存储，后续通过存储服务接口替换为对象存储，不让页面和业务层直接依赖物理路径。

## 10. 安全与可靠性要求

- 密码使用 `crypto.scrypt` 或同等级别算法，不保存明文密码。
- 所有文件接口校验登录状态和资源归属。
- 防止路径穿越：物理路径由内部 ID 拼接，不接受用户路径直接访问。
- 上传文件大小由客户端和服务端双重限制，服务端限制为最终准则。
- 对文件名进行规范化，禁止控制字符和目录分隔符。
- 下载使用服务端生成的文件流，不直接暴露存储目录。
- 删除默认软删除，恢复和永久删除分别校验权限。
- 失败上传清理临时文件，避免产生孤儿文件。
- 重要操作写入可追踪日志，至少包括用户、资源、动作、时间和结果。

## 11. 测试与验收方案

### 11.1 后端接口测试

必须覆盖：

- 登录成功、密码错误、缺少字段和会话失效。
- 用户 A 无法读取、下载、修改或删除用户 B 的文件。
- 创建目录、重复目录、非法名称和多级目录。
- 文件上传成功、超限、重复、磁盘失败和失败重试。
- 文件下载成功、文件不存在和无权限。
- 删除、回收站查询、恢复、原目录不存在时恢复到根目录。
- 永久删除后元数据和物理文件均被清理。

### 11.2 前端交互测试

必须覆盖：

- 未登录访问受保护页面会跳转登录页。
- 登录成功后进入文件管理页。
- 新建文件夹、进入目录、面包屑返回。
- 上传进度、成功和失败重试展示正确。
- 删除确认弹窗可取消和确认。
- 空目录、加载中、请求错误和无权限状态可见。
- 移动端无横向滚动，主要操作满足触摸尺寸。
- 键盘可完成登录、打开菜单和确认弹窗操作。

### 11.3 交付前检查

- 运行全部自动化测试。
- 运行类型检查、Lint 和构建。
- 验证 Docker 启动、数据库初始化和文件目录权限。
- 在 `375px`、`768px`、`1024px`、`1440px` 下检查布局。
- 检查无控制台错误、无未处理 Promise、无可访问性明显阻断。
- 每个改动完成后创建对应 Git commit。

## 12. 迭代路线

### Iteration 1：可用主链路

登录鉴权、文件夹、文件列表、上传、下载、重命名、删除确认。

### Iteration 2：可恢复管理

回收站、恢复、永久删除、配额显示、异常状态完善。

### Iteration 3：可查找与可分享

搜索、分享链接、有效期、分享密码、基础预览。

### Iteration 4：大文件与协作能力

分片上传、断点续传、版本管理、OnlyOffice、多人协作。

## 13. 设计决策记录

- 首版采用文件列表而不是复杂卡片墙，以提升大量文件场景下的扫描效率。
- 首版使用本地存储以降低部署复杂度，但用存储服务边界隔离未来对象存储迁移。
- 首版默认软删除，避免文件管理器最常见的误删风险。
- 首版不做在线编辑，先确保文件可靠上传、保存、取回。
- 视觉采用轻量 Minimalism：蓝色表达主操作和文件夹，琥珀色表达文件类型，危险操作使用红色；不依赖阴影、渐变和装饰动画制造层次。
